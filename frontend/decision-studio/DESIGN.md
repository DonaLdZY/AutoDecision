# Decision Studio 0.1.0 设计记录

日期：2026-10-16。面向本地部署的软件产品评审。本版设计与实现同属上下文 v1.7.0。

## 产品的对象

用户经营一个持续存在的数据项目。对话负责承接需求，算法模型包负责承载可重复执行的能力，调用记录负责保存一次决策的证据，研发任务负责补齐能力缺口。

首页的任务是让用户明确：当前在用哪个项目的数据、已有能力是否可复用、这次做了什么、结果和模型版本在哪里。研发中心作为独立工作区存在，不能把一次耗时训练作为每次提问的默认路径。

```text
项目导航              决策对话                           项目上下文
┌──────────────┬───────────────────────────┬────────────────┐
│ 当前项目      │ 当前需求                   │ 数据快照       │
│ 新建对话      │ 用户提问                   │ 数据表         │
│              │ 助手说明                   │                │
│ 决策对话      │ ┌ 可复用能力与执行凭据 ───┐ │ 可用模型包      │
│ 数据项目      │ │ 数据 → 预测 → 优化     │ │ 冻结版本       │
│ 算法模型包    │ │ 结果、曲线、待审核建议   │ │                │
│ 研发任务      │ │ 输入对齐 / 调用详情     │ │ 正在研发的能力  │
│ 调用记录      │ └───────────────────────┘ │                │
│              │ 继续提出需求              │                │
│ 历史与设置    │ 输入 + 项目数据 + 模型包    │                │
└──────────────┴───────────────────────────┴────────────────┘
```

没有选择“空白聊天框 + 附件”的通用聊天布局：用户需要先看到项目已拥有的计算能力，以及能力复用后的结果形态。初始页面因此展示一个完整的组合调用案例。

## 视觉系统

| 角色 | 取值 / 用途 |
|---|---|
| 工作区底色 | `#F5F7F8`，冷白，长时间分析与操作 |
| 内容面板 | `#FFFFFF`，以细边框区分数据与操作 |
| 主要文字 | `#20363E`，蓝灰，主标题与重要数值 |
| 品牌主色 | `#11796D` / 操作按钮 `#297D68`，决策与执行入口 |
| 能力与复用辅助色 | `#EAF4EF`，浅绿，冻结能力与可用状态 |
| 搜索/失败辅助色 | 淡蓝用于融合与研发；低饱和琥珀用于失败、缺口、待审核 |

中文和正文使用系统 `Segoe UI / Microsoft YaHei / system-ui`，数值使用 `Bahnschrift`，代码使用 `Cascadia Code / Consolas`，不依赖在线字体。标题 23–26 px，正文 12–13 px，辅助文字 10–12 px。边框、间距和数值对齐承担信息层次，避免大面积装饰。

主要布局是 228 px 侧栏、可伸缩对话与 275 px 上下文栏。1050 px 以下收起上下文栏，760 px 以下侧栏转为抽屉；详情使用原生 modal dialog，可滚动、可用 Escape 关闭、保持键盘焦点。图表轴文字独立于 SVG 曲线缩放，避免长屏下文字变形。

标志性组件是**决策执行凭据**：对话里的卡片同时呈现能力依赖、冻结版本、关键结果、示意图、业务建议和执行详情入口。另一个重要组件是候选程序搜索树：展示候选代码改进、失败修复与跨分支融合，而不是把业务选项枚举画成算法研发。

## 交互决策

1. 项目选择是全局上下文，所有会话与能力均有 projectId。
2. 能力已经覆盖时直接复用；不足时给出任务建议，用户确认再创建研发任务。
3. 模型包详情同时服务业务用户和开发者：先展示用途、适用边界，再看输入输出、文件与调用、版本与来源。
4. 用户看到的是执行记录与可检查的输入映射，不展示模型隐藏思维过程。
5. 输入适配是明确步骤；语义冲突阻止执行，单位换算需要确认。
6. 研发完成不直接等于生产验收或发布。报告页面保留独立验证、未执行的生产验收与显式发布确认。
7. 已发布能力回到同一项目中可用；同样的预设需求再次到来时复用它。
8. Demo 状态保存在浏览器，设置页提供导出与带确认的重置。

## 实际评审后的修正

- 修正对话 grid/flex 的最小高度，让消息滚动、输入区常驻，不被长结果挤出视口。
- 增大辅助文字并提高文字对比度；压缩凭据的冗余垂直间距。
- 使用 HTML 轴标签配合 SVG 曲线，避免 SVG 非等比拉伸文字。
- 补充弹窗 Tab/Shift+Tab 环绕与 Escape 恢复，避免键盘焦点离开弹窗。
- 新任务按意图 → 数据 → 搜索 → 验证 → 报告逐阶段推进，不跳过数据阶段。
- 手机保留完整调用凭据和输入框，数据与能力从导航入口访问。

## 定型后需要继续设计的部分

跨项目能力授权、模型版本升级/废弃、多人权限、数据源管理、真实失败/取消/重试、运行队列与实际预算、输入参数表单、编排计划审批、模型漂移及更新任务。这些没有伪装成当前已实现的后端能力。

在真实接入前应先评审：默认是否直接展示项目最近会话；组合调用是否需要一律先确认；任务详情保留弹窗还是进一步拆为可深链接的整页；跨项目复用是否作为后续单独功能。

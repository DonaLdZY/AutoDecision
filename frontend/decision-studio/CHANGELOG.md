# Decision Studio 版本记录

## 0.2.6 启动与开发入口补充 — 2026-10-20

- 新版成为 AutoDecision 默认产品前端和后续界面开发重点；根 README 及本目录 README 补齐安装、完整启动、开发热更新与代码导航。
- 根目录 `启动AutoDecision.cmd` / `start.ps1` 默认启动三个 Core、Gateway 和新版 5178；开发使用 `start.ps1 -Dev` 或 `scripts/dev-up.ps1`。
- 各启动/停止/重启脚本统一委托 `scripts/studio.py`，共享进程状态和日志，旧 5173 需显式选择；`start-studio.ps1` 默认包含 Core，兼容 `-WithCore`。
- Gateway CORS 加入 5178。25 项回归、Windows 完整生命周期与真实浏览器导航验证通过，未更改业务协议或模块版本。详情与附件见项目上下文 v1.8.11。

## 0.2.6 — 2026-10-19

- 决策对话的 `clarify`、`reuse` 和 `research` 计划均可直接转为新研发任务；研发弹窗会带入计划目标或最近用户消息。
- 研发草稿润色请求携带当前对话、计划、项目历史认知和已有模型包上下文，返回结果仍可人工修改后保存。
- 真实工作台版本、后端版本和前端状态版本同步到 0.2.6；新增真实本地浏览器冒烟脚本 `e2e/todo_acceptance.py`。
- AutoRealize 项目级共享认知缓存增加旧格式防护；缓存文件按内容 fingerprint 增量复用，历史 QDI 来源状态与当前问题重查策略纳入测试。
- 回归补充：`research`、`reuse`、`clarify` 三种对话计划均可开研发弹窗；所选项目/目录会进入润色请求，跨项目计划包不提交；延迟润色响应不会覆盖用户编辑。见 AutoDecision 上下文 v1.8.10 审计附件。

## 0.2.1 — 2026-10-16

- 新安装默认只有一个名为 `deepseek` 的模型配置，角色 ID `autoRealize`、`autoMlCode`、`autoMlFeedback` 共用它；默认向量检索角色关闭。
- AutoRealize 图像认知与数据分析角色共用模型 ID、API 地址与提供方密钥，不再提供独立视觉模型分配。旧任务配置仍兼容读取。
- 仅将精确匹配且没有任何密钥或自定义修改的旧五模型出厂配置合并为单个默认模型；用户自定义配置不会因升级被删除。
- 设置页标题调整为“模型配置”“角色模型分配”；数据分析标注需要多模态模型；移除界面中的实现术语与密钥处理说明，将访问令牌/组件地址归入高级设置。
- 图像能力测试用服务端生成的红色测试图片，只验证图片请求/识别能力，不读取用户项目文件或证明生产任务的认知质量。
- 隔离端到端验收的设置检查改为专用协议夹具模型；不向真实模型提供方发请求。

本版本后端回归 148 项通过。Studio 格式检查和构建、旧界面构建、浏览器端到端闭环结果归档于项目上下文 v1.8.1。

## 0.2.0 — 2026-10-16

- 默认入口从合成交互 Demo 切换为真实 Gateway 工作台；`?demo=1` 保留旧 Demo。
- 新增项目、会话、模型包、调用与任务链接的本地 SQLite 持久化。
- 接入已有 TaskStore、readiness、快照、搜索树、报告、方案导出、实验谱系和原任务动作。
- 真实对话规划支持 LLM 计划校验与无 LLM 手动目录模式；不再用固定关键词生成假结果。
- 新增不可变模型包副本、完整文件指纹、合同与来源验证、JSON schema 和有界输入适配。
- 新增单包/最多四步组合调用，记录输入、包、适配和实际本地推理结果；调用幂等且拒绝篡改包。
- 增加 Gateway 令牌、离线/错误/运行中/中断状态与真实设置/readiness 页面。
- 保留 `frontend/ui/` 和 v0.1.0 合成 Demo，未把模拟数据当作真实运行证据。

首个独立前端交互 Demo，对应项目增量上下文 v1.7.0。全部数据、指标、时间、搜索树、预测和路由均为模拟。

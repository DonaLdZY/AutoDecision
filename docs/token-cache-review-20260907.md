## 改进优先级

1. 同一候选的任务合同和完整代码采用一致前缀，审查角色、运行日志和反馈置后，让代码审查与结果审查也能复用同一份代码缓存。当前代码前面的角色说明不同，会限制这部分复用；需要修改后验证实际请求字节和provider遥测。
2. 数据读取、切分、防泄漏、指标计算、训练/推理导出成为引擎提供的可复用基础代码；候选主要生成模型/特征差异。这样可以同时减少生成、代码审查和调试的输入输出，而不通过限制算法家族省token。
3. 建立带稳定ID、完整规则文本和原文定位的权威约束表，其他视图引用同一条规则。先逐条验证来源覆盖、冲突、阈值、单位、缺失条件、评估人口及交付范围，再替换重复改写。不是直接把全部材料压成一个摘要。
4. QDI近期结果、累计解释、动作账本中重复的事实用证据ID关联，完整证据仍可取回；未知事项、来源矛盾和当前行动所需证据保持可见。不能只在末尾截断历史。
5. 固定JSON结果先由确定性程序校验和解析，LLM聚焦模型选择理由、约束偏离与复杂异常。防泄漏与训练/推理复用审查仍然保留，不能为了减少调用而绕过。

主要观察指标应是每个合格候选的总输入、已知未缓存输入、输出、失败/返修调用数、约束覆盖和最终效果。缓存命中token仍属于输入token，缓存主要改变计费与prefill开销；不能只以总token降幅或单个命中率判定改进成功。
